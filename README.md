# Sprint_10

Автотесты учебного сервиса «Яндекс.Маршруты».

Кузина Валерия, поток 37.

## Что проверяется

Стенд: https://qa-routes.education-services.ru/.

29 проверок в Google Chrome:

| Модуль | Сценарии |
| --- | --- |
| `test/test_route_map.py` | Две точки и подписи адресов на карте, оба направления маршрута |
| `test/test_route_picker.py` | Блок выбора маршрута; одинаковые адреса, бесплатная поездка за 0 минут |
| `test/test_taxi_preparation.py` | Переключение режимов, стоимость и время; шесть видов транспорта; кнопки такси и Драйва |
| `test/test_taxi_tariffs.py` | Шесть тарифов, активный тариф, описания по наведению, поля заказа |
| `test/test_taxi_order.py` | Рабочий тариф со столиком, поиск машины и обратный отсчёт; водитель, детали поездки и отмена |

Используются только два адреса из задания: «Хамовнический вал, 34» и «Зубовский бульвар, 37».
У «Оптимального» и «Быстрого» время на этом маршруте совпадает после округления до минут.
Чтобы проверить именно обновление времени, перед выбором каждого из этих режимов устанавливается пеший маршрут в режиме «Свой».

## Установка и запуск

Нужны Python 3.10+ и установленный Google Chrome. Команды для PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest
```

ChromeDriver подбирает Selenium Manager. При первом запуске нужен доступ к интернету.
По умолчанию Chrome запускается без видимого окна. Для просмотра выполнения:

```powershell
.\.venv\Scripts\python.exe -m pytest --headed
```

Можно задать переменные окружения `BASE_URL`, `CHROME_BINARY` и `CHROMEDRIVER`.
Для каждого теста создаётся отдельный браузер; после проверки он закрывается.

## Найденные ошибки и отчёт

У тарифов «Сонный» и «Разговорчивый» перепутаны описания — [ROUTES-001](docs/bugs.md).
Тесты сравнивают описания с требованиями задания. Эти два случая помечены `xfail` с причиной и `raises=AssertionError`.
Ожидаемый результат обычного запуска: **27 passed, 2 xfailed**.
Включён `xfail_strict`: если дефект исправят, неожиданно успешная проверка завершит прогон с ошибкой, чтобы отметку пересмотрели.

В репозитории сохранён [отчёт Allure](allure-report/index.html), полученный с `--runxfail`:
**27 passed, 2 failed**. Так ошибки стенда видны в отчёте как падения проверок.
Скачать проект и открыть `allure-report/index.html` в браузере: это автономный HTML-файл со скриншотами и шагами.
На странице GitHub HTML отображается как исходный код.

Для повторного получения такого отчёта:

```powershell
.\.venv\Scripts\python.exe -m pytest --runxfail
npx --yes allure@3.33.0 generate allure-results --output allure-report --clean
```

Для генерации нужен Node.js. Первая команда вернёт код 1, пока дефект воспроизводится; после неё отдельно выполнить команду генерации.
Обычный запуск `pytest` также записывает результаты в `allure-results`, но с отметками XFAIL.
Параметр `--clean-alluredir` очищает результаты перед каждым запуском.

## Структура

- `test/` — тестовые классы по блокам задания.
- `pages/` — Page Object и компоненты карты и окна заказа.
- `locators/` — локаторы страниц.
- `data.py` — адреса, тарифы, тексты и параметры проверок.
- `conftest.py` — фикстуры и скриншоты при падении или XFAIL.
- `helpers/browser_factory.py` — настройки Chrome.
- `allurerc.json` — настройки автономного отчёта на русском языке.

Используются явные ожидания WebDriverWait и ActionChains для наведения курсора.
Таймер поиска проходит естественным образом. `sleep`, неявных ожиданий и изменения состояния приложения через JavaScript нет.
